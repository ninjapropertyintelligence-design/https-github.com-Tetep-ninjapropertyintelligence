# Independent implementation plan — planning only

**No application has been implemented.** The existing [implementation plan](IMPLEMENTATION_PLAN.md) and [architecture proposal](TECHNICAL_ARCHITECTURE.md) describe Next.js, TypeScript, Tailwind CSS, and Supabase. This plan adds the verified spatial-media scope without asserting IDS internals.

1. Confirm product scope and rights: which organization/location/inspection flows matter; media ownership/licensing; whether Matterport, Autodesk, and any drone provider accounts can be used; retention and data residency. Use synthetic data, original branding, and independent UI design.
2. Build tenancy/auth foundation: Supabase Auth, organization memberships, tenant-scoped Postgres RLS, private Storage policies, audit logging, denial tests. Do not expose secret/service-role credentials in the browser. Verify current SDK/docs and changelog at implementation time.
3. Implement read-only catalog: organization/location/project navigation, typed lists/filters/tabs, map/list, media metadata, 360 gallery, raster catalog, 3D-embed catalog. Define accessible loading/empty/error states and stable route behavior.
4. Add spatial adapters independently: native 360 renderer, Matterport embed where model rights permit, Potree-hosted converted point cloud, Autodesk viewer/link integration if licensed. Each adapter needs authorization, expiry/error handling, content-security policy, provenance, and provider-specific tests. [Verified target display boundaries](INTEGRATION_CATALOG.md) do not dictate the new backend.
5. Add assignment/inspection read views and verified progress displays, then separately specify writes, uploads, reports, asset registry, analytics, and AI features; unverified features must have new product requirements before implementation.
6. Verify end-to-end with synthetic fixtures: browser → authorized API → RLS/Storage → viewer; keyboard/accessibility/responsive states; provider outage and expired-link handling; cross-tenant denial; performance on large imagery/point clouds. No production Phygii data import.

Potential additional systems: PostGIS for spatial queries; a licensed map source; a controlled background processor for raster/point-cloud conversion; secure provider credential vault. These are proposed, not confirmed target dependencies. Supabase security guidance informed the proposed membership-scoped RLS, private Storage access, and avoidance of user-editable authorization metadata ([RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage](https://supabase.com/docs/guides/storage/security/access-control)). The 2026-10-20 changelog flags an upcoming TLS 1.2 cipher retirement and database minor-version changes; recheck before implementation.
